  **Check 2 — the item is right, and it carries a lean, so it is read as a draft.** Measured: the row says "the open, act `0`, is sent only from that act's delivery and stays on the concurrent runner …, so a read is never ordered and never stalls a listing behind it" (`docs/SDD.md:L532`). The one-call form is the price of that, and the cost is bounded: one read of one contained file, and no read at all when the check refuses (`open_relative_link.rs:L203`, `test_open_relative_link_does_nothing_for_what_is_not_a_contained_file`: five refused paths, `read_ran` false for each).

### 5.4 — A relative link to a folder is drawn as a control that does nothing, and the closed node set has no way to say so

- **Bucket:** 5. Raised from downstream — an item from a seat that did not write the SDD
- **Verdict:** answered
- **Why:** Answered, from scratch: the item offers two routes and decides neither, so there is no draft. The second route is taken — a contained folder is an *external* node, inert, destination readable — and the first is declined with its reason.

  **Check 1 — mine, in the CTO's seat; the record it moves is raised where it belongs.** The edit lands in § 3's `MarkdownDocument` entity, the CTO's; it commits nothing to a person or an outside party; the bar it serves is UX-I12's, settled and readable, and FR-32's. The item is one question with one seat, not two: the ADR "follows whichever route is taken", as the item says, so it is a consequence of this answer and not a second decision.

  **Check 2 — the question is the right one, and it hides nothing.** Measured: `link_target` answers `Relative(entry.path)` for any `Ok(entry)`, folder or file (`references.rs:L94-L96`); `ContainedEntry` carries a `kind` the renderer drops (`fs_reader.rs:L420-L423`, `EntryKind::Folder | File` at `:L103-L106`); CP-1072's test pins the drop deliberately — "whether that entry is a file is decided when the link is activated" (`tests/unit/markdown_renderer.rs:L682-L685`); the page gives every relative node a link attribute (`MarkdownPageView.swift:L279-L281`) and the link cursor, since `linkTextAttributes` is emptied but the cursor stays (`:L51-L53`); activation on a folder: `link_file` → `contained_file` → `None` → `Pending` (`folder_model.rs:L305-L307`; `open_relative_link.rs:L203-L245`, `src` among the five refused), decoded as `.nothing` and dropped (`BridgePayload.swift:L396-L400`; `WorkbenchView.swift:L279`). So the item's facts hold: a control that does nothing, which UX-I12 forbids — "it is a control only where activating it does something" (`docs/UXD.md:L324-L327`). **Why the second route.** *External* is defined by behaviour, not by where the path points: the entity says "*external* (inert, its destination readable)" (`:L737-L738`), and the renderer already files a missing in-folder path under it (`Err(_) => External`). A folder is a contained entry nothing opens — the panel opens files (UX-I12; FR-32 names "a relative link to a file"), and a tree selection of a folder is an expand, which a link in prose has no business raising. So the form that exists is the right one, and the change is one arm of a `match` and the sentence that defines the forms. **Why not the first.** A `kind` on a relative node has one reader, the page's control decision, which the two forms already make; every other consumer — the bridge's activation path, the containment check, the hostile corpus's assertions — is indifferent to it. ADR-0025 says a new node kind takes a record; a field is not a kind, but widening the type for a decision the type already carries is a worse record to write than narrowing a definition. **What the answer costs that CP-1072 was protecting:** the kind is read at render and never re-asked. The test's reason — decide at activation — survives in the bridge, which still checks at activation; what moves is only which node the page draws as a control, and the two stale cases are named below.

  **Check 4.** *Empty* — a destination that is empty or `.` reaches the containing folder, a folder, so it is inert; today it is a control that does nothing. *Absent* — a missing path is external already. *Stale, both ways* — a file replaced by a folder after the render is a control whose activation answers `pending`, the case `test_a_link_target_swapped_for_a_symlink_out_after_the_document_rendered_does_nothing` (`open_relative_link.rs:L257`) already accepts for the symlink; a folder replaced by a file stays inert until the document is read again, and a change at the target's path does not re-read the document — only the open file's own change does (`follow-the-file`).
