# Dependency review — every name on `checks/deps.allow`

The one-time transport review `docs/nfdr.md` QC-3 owes, recorded as code beside the list it reviews and
landing in the same commit as that list and `Cargo.lock` (QC-26, CP-301, CP-302). It covers every name on
the list at that commit: the 17 names QC-3 says were never reviewed, the three added at `21589c7`
(`bitflags`, `errno`, `rustix`), the 20 the grammar-engine change added, and the six `2026-10-03_git-reader-probes-the-root` adds (`git2`, `jobserver`, `libgit2-sys`, `libz-sys`, `pkg-config`, `vcpkg`).

## The engine chosen

**The grammar engine is tree-sitter**: the `tree-sitter` runtime, `tree-sitter-highlight`, and one
grammar crate for each floor language (`tree-sitter-python`, `tree-sitter-bash`,
`tree-sitter-javascript`, `tree-sitter-json`, `tree-sitter-yaml`, `tree-sitter-toml-ng`), compiled from C
into `nozoki-core` through `cc`, with nozoki's own query files compiled in. This answers the open question
on the grammar engine in `docs/SDD.md:L4521-L4524` (CP-303). Hand-written lexers would add no names but
would put six grammars' worth of lexing in the core; `syntect` needs vendored Sublime syntaxes for TOML and
its default dump holds far more than six grammars (`change_design.md` § Architect Review Notes).

## The question

QC-3's question, from `docs/nfdr.md:L105-L108`: the review judges each name "against this entry's domain —
does it, **in the features the lockfile resolves**, link a network transport — and not only whether the
addition is deliberate. A name alone cannot answer that: `cargo tree --offline --locked -e features -i
<crate>` is what the review reads for a crate".

## How each row was read

- **Version** is the one `Cargo.lock` resolves.
- **Evidence** is that `cargo tree` command, run offline against the lock that lands, and the features it
  resolves for the crate. A transport that a feature turns on would show there, and none does.
- **Verdict** also rests on a scan of the crate's registry copy, the one the lock resolved, for `std::net`,
  `TcpStream`, `UdpSocket`, `getaddrinfo`, `connect(` and `socket(` in its `.rs`, `.c` and `.h` files.
  A hit is read in place and said so in the row.
- **Licence** is the `license` field of the crate's own `Cargo.toml` in that registry copy, recorded for
  the 20 names this change adds (CP-303).
- Rows are sorted as `checks/deps.allow` is sorted. Coverage is measured with `comm`, not counted by eye:
  the names in the first column, compared with the list's `cargo:` section, print nothing on either side.

**Every name below but one links no network transport. `libgit2-sys` does not carry the verdict "no transport" and its row says why:** its HTTPS and SSH are off, its `git://` and `http://` transports are compiled in and no feature removes them, and the property that holds is at the shipped executable's link, not at the build of the library.
